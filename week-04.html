<!-- 01 / why responsive design? -->

One site. Every screen.

People visit your page on phones, tablets, laptops, and giant monitors. A layout that fills a laptop will overflow a phone.

Responsive design is the practice of building one page that adapts its layout to whatever screen it lands on.

<!-- 02 / the main tool: media queries -->

Different styles at different sizes.

A media query is a block of CSS that only applies when the screen meets a condition — like "the viewport is 600px wide or less."

You write your default styles once, then add media queries to adjust them as the screen gets smaller or larger.

<!-- 03 / anatomy of a media query -->

Reading the syntax.

@media screen and (max-width: 600px) {
  body { font-size: 14px; }
}
@mediathe keyword that begins a media query.
screenthe media type — almost always screen (vs print).
(max-width: 600px)the condition — apply this when the viewport is ≤ 600px. That width is a breakpoint.
{ … }the styles to use when the condition is true.

<!-- 04 / a full example -->

Smaller screen, smaller text.

style.css
/* default styles */
body { font-size: 16px; }

/* when the screen is ≤ 600px */
@media only screen and (max-width: 600px) {
  body { font-size: 14px; }
}
Hello World!
≤ 600px 14px
Hello World!
> 600px 16px

Above the breakpoint, the default 16px applies. At 600px or below, the media query takes over and shrinks the text to 14px.

<!-- 07 / Chrome DevTools -->

Your everyday testing tool.

Open it
  • Right-click the page → Inspect, or press F12.
  • Toggle the device toolbar: Cmd/Ctrl + Shift + M.
  • Pick a device and see your layout emulated instantly.
⌘⇧M device toolbar
The panels
  • Elements — inspect & live-edit HTML and CSS.
  • Console — debug JavaScript.
  • Audits / Lighthouse — find performance issues (big images, bloated CSS).

Emulating devices and screen sizes is the single most useful feature for getting responsive layouts right.

<!-- 08 / Xcode & the iOS Simulator -->

Virtual iPhones & iPads.

Xcode is Apple's development environment for macOS. It includes the iOS Simulator — virtual iPhone and iPad devices you can test on without owning them all.

Install Xcode → open it → Open Developer Tool ▸ Simulator. Choose a device and iOS version, then browse your site in the Simulator's built-in Safari.

Good to know
  • Great for checking layout across many iOS sizes.
  • It's a virtual environment — some features (geolocation, device APIs) may not work.
  • Not a substitute for a real device.

<!-- 09 / best practices for mobile testing -->

Then test on the real thing.

Emulators and simulators get you 90% of the way. But screen sizes, resolutions, touch, and performance all behave a little differently on actual hardware.

  • Test on a variety of devices, not just one.
  • Use real devices whenever you can.
  • Cover different screen sizes and resolutions.

<!-- 10 / CSS frameworks -->

A head start on styling.

A CSS framework is a pre-built library of styles and components — grids, buttons, forms, navigation — that make it faster to build responsive, consistent pages.

Instead of styling everything from scratch, you drop in ready-made, tested pieces and customize them.

<!-- 11 / two popular frameworks -->

Bootstrap & Material.

Bootstrap · by Twitter
  • Responsive, mobile-first framework.
  • A flexible grid system for layouts.
  • Ready-made components: forms, buttons, modals, navbars.
  • Free & open-source.
Material-UI · by Google
  • Implements Google's Material Design language.
  • Consistent look & feel across platforms.
  • Works with React, Angular, Vue.
  • Free & open-source.

// both give you a polished, consistent starting point — then you customize to make it yours.
