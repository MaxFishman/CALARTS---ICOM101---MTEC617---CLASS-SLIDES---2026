<!-- 01 / the position property -->

Break out of the default flow.

By default every element is position: static — it sits where the normal document flow puts it. Change position and you unlock four offset properties to nudge it around:

topmoves the element down from the top.
bottommoves it up from the bottom.
leftmoves it away from the left (to the right).
rightmoves it away from the right (to the left).

Values in px, em, or % — but offsets do nothing while position is still static.

<!-- 02 / position: relative -->

Nudge from where it was.

style.css
.green-box {
  background-color: green;
  position: relative;
  top: 50px;
  left: 120px;
}
output
original spot

relative positions an element relative to its own default spot — here, 50px down and 120px right. The space it used to occupy is left behind (the dashed outline).

<!-- 03 / position: fixed -->

Pin it to the screen.

style.css
.title {
  position: fixed;
  top: 0px;
  left: 0px;
}
a fixed header
My Awesome Website ← stays put

Hello World! I'm learning to make a website with HTML and CSS.

Scroll this little window…

…and notice the blue bar never moves.

A fixed element is removed from the flow and pinned to the viewport.

This website is in progress. Please come back later!

fixed locks an element to a spot on the screen — it ignores scrolling. Great for headers, nav bars, and "back to top" buttons.

<!-- 04 / position: sticky -->

The best of both.

style.css
.box-bottom {
  background-color: darkgreen;
  position: sticky;
  top: 240px;
}
scroll me — real sticky

Scroll down inside this window.

The blue bar below flows normally at first…

📌 sticky — sticks at the top

…then sticks to the top once you reach it.

Keep scrolling.

It stays pinned while its container is in view.

When the container ends, it "unsticks" and scrolls away.

This website is in progress. Please come back later!

sticky scrolls normally until it hits your offset (top: 240px), then sticks there until its parent scrolls past.

<!-- 05 / z-index — stacking order -->

Which box is on top?

style.css
.blue-box {
  position: relative;
  z-index: 2;
}
.green-box {
  position: relative;
  z-index: 1;
}
output
z-index: 2
z-index: 1

When positioned boxes overlap, z-index sets their depth — a higher number sits in front. Think of it as how close a layer is to you.

<!-- 06 / foreground vs background color -->

Two colors, two properties.

style.css
h1 {
  color: red;            /* the text */
  background-color: gold; /* behind it */
}
output

Hello World!

color sets the foreground (usually the text). background-color paints the box behind it.

<!-- 07 / opacity — transparency -->

From invisible to solid.

style.css
.overlay {
  opacity: 0.5;
}
a 50% white overlay
opacity: 0.5

Opacity runs from 0 (fully invisible) to 1 (fully solid). 0.5 is half-transparent — perfect for overlays that let the layer behind show through.

<!-- 08 / background-image -->

Put a picture behind it.

style.css
/* a file inside your project */
.main-banner {
  background-image: url('images/mountains.jpg');
}

/* …or a link on the web */
background-image: url('https://…/photo.jpg');
output
My Awesome Website

The value is a url(…) — a relative path to a file in your project (images/mountains.jpg) or a full web address. (Preview shows a stand-in.)

<!-- 09 / gradients — color, blended -->

Backgrounds that blend.

style.css
background: linear-gradient(to right, red, blue);

background: radial-gradient(circle, red, blue);
output
linear-gradient → left to right
radial-gradient → out from center

A gradient is a smooth blend between colors — no image file needed. linear runs in a direction; radial spreads out from a point.

<!-- 10 / state changes: :hover -->

Styles that react.

style.css
a {
  color: purple;
  text-decoration: underline dotted;
}
a:hover {
  color: goldenrod;
  text-decoration: underline;
}
hover the link →

Read our latest article to learn more.

:hover applies styles only while the pointer is over an element — a state change. Right now that change snaps instantly… let's make it smooth.

<!-- 11 / CSS transitions -->

Animate the change.

A transition controls how a state change happens over time — instead of snapping, it eases. You can control four things:

propertywhich CSS property animates.
durationhow long it takes.
timinghow it accelerates.
delayhow long to wait before it starts.

// hover the buttons on the next slides — the demos are live.

<!-- 12 / property + duration -->

The two essentials.

style.css
.btn {
  transition-property: all;
  transition-duration: 0.4s;
}
hover the button →

A transition needs at least a property and a duration. Time is in seconds or milliseconds — 1s, 0.4s, 400ms. (A blink is ~400ms — a good gut-check for "snappy.")

<!-- 13 / transition-timing-function -->

The pace of the motion.

easeslow → fast → slow. The default.
linearconstant speed the whole way.
ease-instarts slow, accelerates, stops abruptly.
ease-outstarts abruptly, slows to a gentle stop.
same distance, different pace
ease
linear
ease-in
ease-out

All four dots travel the same distance in the same time — only the pacing differs.

<!-- 14 / transition-delay -->

Wait, then go.

style.css
transition-property: width;
transition-duration: 750ms;
transition-delay: 250ms;

Here a width change waits 250ms, then animates over 750ms. Default delay is 0s — no wait.

<!-- 15 / the transition shorthand -->

All four, one line.

style.css
/* property duration timing delay */
transition: color 1.5s linear 0.5s;

/* chain several with commas */
transition: color 1s linear,
            font-size 750ms ease-in 100ms;

/* animate everything the same way */
transition: all 1.5s linear 0.5s;
order mattersproperty → duration → timing → delay.
comma =combine different transitions in one rule.
allapply the same transition to every changing property.

Gotcha: to set a delay you must also set duration — the browser reads the first time value as the duration.
