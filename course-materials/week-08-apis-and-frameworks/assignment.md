## Overview

This week you learned that an **API** (Application Programming Interface) is a set of rules and tools that let two software applications communicate — one app can share data and functionality with another without either knowing how the other is built inside. You also met **frameworks**: sets of pre-built software components that give you a foundation for building web applications so you start from proven structure instead of wiring up everything yourself.

This homework, "Connect to the wider web," asks you to go out and touch these ideas for real: find an API, embed one into your project, and take a first look at a framework. Closing thought: **stand on the shoulders of giants.**

## What you'll practice

- Reading an API's documentation to understand what it offers.
- Embedding an existing API into your own project so you reuse code instead of building from scratch.
- Skimming a framework's homepage to see what it gives you "for free."
- Reflecting on which framework fits a project you'd like to build, and why.

## The assignment

Work through each step below. These are the exact tasks from the lecture checklist, expanded with a little detail — there is nothing extra to do beyond these four items.

1. **Find a free public API and read its docs.** Pick something that interests you — weather, jokes, dog photos, or anything similar. Open its documentation and get a feel for what data or functionality it provides and how you would ask for it.

2. **Embed one API in your project.** Add a single API to a project of yours — a **map**, a **video**, or a **font service**. The goal is to see your app borrow another app's powers: you use the result without ever seeing the other system's code.

3. **Skim a framework's homepage — React or Django — and note what it gives you for free.** Spend a few minutes on the homepage and jot down what the framework provides as a foundation (for example, structure and pre-built components you'd otherwise build yourself).

4. **Write two sentences:** which framework fits a project you'd like to build, and why? Remember there is no single "best" — each framework has strengths and trade-offs, so pick one that fits the project (and the language you know).
